## Course Description

Gain a deeper understanding of HTML (for structure) and CSS (for style) while creating multi-page
websites suitable for businesses and organizations. Explore web development's more advanced
techniques useful for improving usability and user experience. Plan and design websites for desktop
and mobile users.

## Course Learning Outcomes

1. Utilize the most recent HTML elements and CSS properties to create and style webpage content.
2. Plan, construct, and style webpage layouts for multiple devices and users.
3. Construct website features commonly found on large website projects.
4. Integrate site management concepts such as SEO and accessibility into a website’s plan, layout,
   and design.

## Class Topics and Schedule (Winter 2027)

- **Week 1 (Jan 4–10) — Modern Dev Workflow & Semantic Foundations** — Semantic HTML5 landmarks,
  DevTools basics, Git/GitHub PR workflow, Vite starter kit, automated CloudFront deployment
- **Week 2 (Jan 11–17) — Modern CSS Architecture & Extension Tools** — `@layer`, CSS custom
  properties (design tokens), native nesting, `clamp()`, logical properties, Sass/PostCSS context
  _(due Tuesday, Jan 19 due to MLK Day)_
- **Week 3 (Jan 18–24) — Responsive Layout Systems** — Flexbox, CSS Grid, Subgrid, Container
  Queries, responsive `<picture>` media; _Final Project Milestone 1 (Proposal) due Mon, Jan 25_
- **Week 4 (Jan 25–31) — Usability, UX & Web Accessibility** — WCAG 2.2 AA, keyboard navigation,
  focus states, color contrast, `prefers-reduced-motion`, DevTools Accessibility Tree & axe audits
- **Week 5 (Feb 1–7) — Large-Scale Navigation & Native UI Primitives** — Multi-level nav,
  breadcrumbs, footer sitemaps, `<dialog>`, Popover API, `<details name="...">`, minimal progressive
  JS
- **Week 6 (Feb 8–14) — Designing Accessible Web Forms** — Semantic labels/fieldsets, mobile
  `inputmode`/`autocomplete`, native validation (`:user-valid`/`:user-invalid`), accessible error
  states; _Final Project Milestone 2 (Design Document) due Mon, Feb 15_
- **Week 7 (Feb 15–21) — CSS Frameworks: Tailwind CSS & Multi-Page Reuse** — Tailwind CSS v4 with
  `@theme` in Vite, framework tradeoffs, avoiding header/footer copy-paste drift across multi-page
  sites
- **Week 8 (Feb 22–28) — SEO, Performance & Site Management** — Metadata, Open Graph, JSON-LD
  (`Schema.org`), `robots.txt`/`sitemap.xml`, Core Web Vitals (LCP/CLS), Lighthouse audits; _Final
  Project Milestone 3 (Initial Structure & Test Deploy) due Mon, Mar 1_
- **Week 9 (Mar 1–7) — Developer Portfolio & Production Launch Concepts** — Personal web developer
  portfolio with technical case studies, DNS/HTTPS/CDN fundamentals
- **Week 10 (Mar 8–14) — Final Project Workshop & Pre-Launch Auditing (catch-up week)** — No weekly
  assignment; complete pre-launch QA and catch up on any missing work before Finals Week
- **Week 11 (Mar 15–19, Finals Week) — Final Project Review & Approval** — _Final Project Milestone
  4: Initial PR Mon Mar 15 -> review comments Wed Mar 17 -> PR approval Fri Mar 19_

## Grading and Assignments

### Grading Standard

I am committed to your success in this course. Keep up with the weekly quizzes and assignments and
reach out whenever you hit a snag. I will accept, and will not penalize, late weekly work through
Sunday, March 14 (before Finals Week)—though getting behind makes catching up much harder.

- **Weekly quizzes (10):** 20%
- **Weekly assignments (9):** 40%
- **Final project (4 equal milestones):** 40%

You may take one **bye week** during the term to skip one weekly assignment for full credit. The
final project milestones and quizzes are all required.

### Help on Assignments

I encourage you to use an AI agent (such as GitHub Copilot, Claude, ChatGPT, or Gemini) to review
your code and pull requests before submitting—pointing out flaws without rewriting your work. Beyond
that, do not get assignment code from classmates or coding agents. Reach out to me if you need help.

### Artificial Intelligence Policy

Students may not use GenAI tools in this course to produce course materials or assignments in whole
or in part. All work you submit for this course toward completion of course requirements must be
your own original work done specifically for this course and without substantive assistance from
others, including GenAI. Work you've completed for previous courses or are developing for other
courses this term also should not be submitted for this course.

There are two exceptions:

1. **AI code reviews.** As described under Help on Assignments, you may use any AI agent to review
   your code or pull requests before submitting. Use its feedback to improve your own work; do not
   have it write or rewrite your code for you. Here is a suggested review prompt:

   > "Perform an adversarial review of `<your-github-pr-link>`, pointing out my logical flaws,
   > semantic HTML/CSS and accessibility issues, and syntax problems, without providing full
   > rewrites of my work, in accordance with COCC academic honesty guidelines."

2. **Local IT troubleshooting.** You may use GenAI tools to solve IT problems on your own computer,
   such as trouble with Git, GitHub Desktop, Node and npm, VS Code, or other setup issues.

You may not use GenAI to answer quiz questions or to build your assignments or final project.

**Instructor use of AI.** In the interest of transparency: this course's materials, including this
syllabus, the course outline, reading summaries, lecture notes, assignments, quizzes, and code
examples, were built in partnership with generative AI coding agents (Google's Antigravity and
Anthropic's Claude Code). The agents produced first drafts, which I then reviewed and edited. I am
responsible for all of the content. My recorded lecture videos are entirely my own; I use the
lecture notes and code examples only as rough outlines. The reason for the different rules is that
the purpose of your assignments is for you to build skills by doing the work yourself. For details,
see
["How AI Was Used to Build This Course"](https://github.com/artzte/cocc-web-dev#how-ai-was-used-to-build-this-course)
in the course repository README.

Please see
